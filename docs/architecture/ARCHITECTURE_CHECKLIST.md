# Esparex Architectural Review Checklist

Every pull request or feature implementation—whether authored by a human developer or generated by an AI agent—MUST complete and include this Architectural Review Checklist in the PR description.

```text
Feature Name: <Name of Feature>
Target Module: <apps/web | apps/mobile | core | contracts | ui>

1. Architectural Classification
[ ] Shared Business Logic (@esparex/core / @esparex/contracts)
[ ] Shared UI / Design System (@esparex/ui)
[ ] Platform Capability (Hardware / OS Features)
[ ] Platform Integration (Cloud Services / SDKs)
[ ] Platform UX (Native Interaction / Navigation)

2. Existing Capability & SSOT Search
[ ] Completed Phase 0 Repository Discovery search across packages.
[ ] Existing capability/service found and reused.
[ ] Capability extension applied (no duplicate capability created).
[ ] New capability contract justified (PADR completed).

3. Multi-Platform Support Verification
[ ] Web Desktop: Verified native OS File Browser & browser-native interactions. Zero mobile modals rendered.
[ ] Web Mobile: Verified responsive layout and web capability fallbacks.
[ ] Tablet Web: Verified touch & pointer interaction parity.
[ ] Android Native: Verified native Android device/emulator behavior & permissions.
[ ] iOS Native: Verified native iOS device/simulator behavior & permissions.

4. Shared Business Logic & Contracts
[ ] 100% Shared Business Logic (Zero OS-dependent business rules).
[ ] Contracts defined in @esparex/contracts.
[ ] Pre-computed presentation properties consumed directly by UI.

5. Capability Adapters & Ownership
[ ] Web Adapter implemented in apps/web.
[ ] Android Adapter implemented in apps/mobile.
[ ] iOS Adapter implemented in apps/mobile.
[ ] Single Ownership enforced (zero ad-hoc feature implementations).

6. Automated Quality & Governance Gates
[ ] TypeScript type-check passed (npm run type-check).
[ ] Unit and integration test suites passed (npm test).
[ ] Accessibility WCAG 2.2 AA audit verified.
[ ] Zero architecture debt introduced (zero scattershot platform branching).
```
